# 项目已有功能全景

## 1. 产品定位与当前交付面

Multica/GoClaw Team Runtime 面向人类与智能体协作团队。当前可见产品面的中心不是 README 所描述的完整智能体生命周期，而是以下工作区协作和受治理交付能力：

- 工作区与成员权限；
- 项目、issue、普通任务和 skill；
- 项目需求基线、实现知识、团队知识库；
- Team Control 中的需求、质量、评审、运行证据与独立验收；
- Web、Electron 桌面端、公开站点和文档站；
- 自托管、CLI/守护进程及完整智能体编排仍主要依赖只读遗留运行时。

## 2. 当前 Web 与桌面共同可见的功能

### 2.1 登录、邀请与首次进入

状态：**已实现（静态证据）**。

- 邮箱验证码登录：发送验证码、输入验证码并建立会话；
- 可配置的 Google OAuth 登录；
- CLI 本地回调授权，以及浏览器向桌面端 `multica://auth/callback` 交付令牌；
- 查看个人待处理邀请、批量选择邀请、接受或拒绝单个邀请；
- 没有工作区时创建工作区；
- 当前 onboarding 仅剩“创建或选取工作区”一个步骤。

限制：旧文档所述“运行时、智能体、完成页”等五步 onboarding 已不符合当前代码。

### 2.2 工作区

状态：**已实现（前端与兼容 API 客户端）**；canonical backend 的完整兼容接入仍未完成。

- 创建与切换多个工作区；
- 编辑名称、描述、工作区上下文和头像；
- 查看 slug，修改 issue 前缀并提示现有编号变化；
- 普通成员离开工作区；owner 删除工作区；
- Web 对无权限工作区显示明确状态，桌面端会清理失效标签组；
- 所有工作区页面、查询键和导航都按工作区隔离。

### 2.3 成员、邀请与权限

状态：**已实现（前端与兼容 API 客户端）**；canonical Auth Member 仅为 opt-in SQLite 部分实现。

- 成员列表、搜索和角色筛选；
- 通过邮箱邀请成员，查看和撤销待处理邀请；
- `owner`、`admin`、`member` 三种角色；
- 修改角色、移除成员，并阻止降级最后一位 owner；
- 成员详情页；
- 权限矩阵按当前角色展示工作区、成员、项目、issue、任务和 skill 能力。

### 2.4 项目

状态：**已实现（可见产品面）**。

- 项目创建、读取、编辑和删除；
- 状态、优先级、负责人、图标、描述、起止日期；
- 表格/卡片呈现、搜索、筛选、排序、列显示和置顶；
- 项目进度、issue 数量与已完成数量；
- 项目详情内复用 issue 视图；
- 管理项目资源链接；
- 项目需求基线：草稿、版本、覆盖率、关联/创建 issue、提交评审、批准和撤回；
- 项目回顾记录；
- 进入项目的 Team Control 控制台。

### 2.5 Issue 管理与协作

状态：**已实现（可见产品面，覆盖最广）**。

- 创建、查看、编辑、移动和删除 issue；
- 标题、富文本描述、状态、优先级、阶段、负责人、项目、起止日期、标签和自定义属性；
- 父子 issue 与子项进度；
- 列表、看板、泳道、表格和甘特视图；
- 分组、筛选、排序、分页/增量加载、列选择与调整宽度；
- 多选后批量更新或删除；
- “我的 issue”视图；
- 评论、回复、编辑、删除、解决/重新打开评论线程；
- 评论和 issue 的 emoji reaction；
- 订阅者管理、时间线和页内查找；
- 附件上传、预览、下载和删除；
- issue/项目置顶；
- Pull Request 侧栏及自动关联的客户端入口；
- 验收结论、历史记录，以及从评论提议决策知识。

说明：部分高级视图和集成是否能在某个真实部署中使用，仍取决于兼容后端、数据库迁移和集成配置，本次未做运行验证。

### 2.6 普通任务

状态：**已实现，但产品模型较轻量**。

- 工作区任务列表；
- 新建、修改状态和删除；
- 状态为 `todo`、`in_progress`、`done`、`cancelled`。

这里的普通任务页面不是旧文档中的智能体执行队列/transcript 页面。当前页面没有运行日志、令牌用量、领取、租约或重试操作。

### 2.7 Skill

状态：**已实现（工作区资料管理）**；执行时注入智能体仍属于遗留/未完成迁移。

- skill 列表、搜索和按使用状态/创建者筛选；
- 手动创建或从 URL 导入；
- 查看来源、创建者和使用方；
- 编辑名称、描述和文件树；
- 新增、修改、删除 skill 文件；
- 删除 skill；
- skill 资源标签；
- 创建者/管理员编辑权限与并发修改提示。

### 2.8 知识治理与实现知识

状态：**已实现（可见产品面与客户端契约）**。

- 搜索已发布知识；
- 提议新知识或现有知识修订；
- 支持目标、决策、约束、需求、操作方法、经验和参考等类型；
- 记录修订历史与来源；
- owner、admin 或项目负责人审核候选；
- 批准、拒绝或隔离知识候选；
- issue 验收结论和项目回顾作为实现知识历史。

### 2.9 Team Control

状态：**已实现，是 canonical backend 当前最完整的端到端切片**。

- Web 与桌面共用项目控制路由 `/{workspace}/projects/{project}/control`；
- 展示项目投影头、节点、边、证据、检查和独立验收；
- 需求、质量、评审、运行、治理和成员七个视图；
- 创建需求/任务、缺陷、风险、评审发现、知识候选和运行请求；
- 使用命令 ID 与预期 head 做幂等和并发冲突控制；
- SSE 增量事件、断线续传、权限漂移时终止；
- 证据清洗标记、确定性检查和独立 DoneGate；
- canonical 控制面提供 SQLite 持久化、事件哈希链、重放与投影。

限制：控制面是独立入口，不等于旧 Multica HTTP API 已整体迁移；生产身份依赖上游身份解析器，默认无身份时拒绝访问；PostgreSQL 生产可用性未得到集成测试证明。

### 2.10 搜索、导航与个人设置

状态：**已实现**。

- 全局命令面板，搜索 issue、项目和成员；
- 最近访问的 issue、页面导航、新建 issue/项目、主题切换和复制链接；
- issue 与项目服务端全文搜索客户端；
- 账号姓名、描述与头像；
- 浅色、深色、跟随系统主题；
- 英文、简体中文、日文、韩文；
- IANA 时区、评论栏固定、issue 链接新标签偏好；
- 键盘快捷键设置；
- PAT 创建、一次性查看、复制、过期时间和撤销；
- 工作区标签与自定义属性的创建、编辑、归档/删除。

### 2.11 桌面端专属能力

状态：**已实现（代码与测试）**。

- 按工作区分组的多标签页、重排、历史和状态持久化；
- 新建工作区、邀请和 onboarding 使用全窗口 overlay；
- `multica://` 登录和邀请深链接；
- 独立 issue 窗口和跨工作区导航；
- 失效工作区标签自动恢复；
- 路由错误页、关闭/重载标签；
- 自动更新检查、后台下载、退出时安装和更新偏好；
- 渲染器冻结/崩溃诊断，且遥测路由会去除工作区 slug 等标识。

当前桌面设置仅额外注入“更新”标签。旧文档提及的本地 daemon 管理卡片和沉浸模式未在当前路由/设置入口中确认。

### 2.12 公开网站与文档站

状态：**已实现**。

- 官网首页、关于、用例索引与详情、更新日志、下载和联系销售页面；
- 下载页展示桌面/CLI 安装入口；
- 独立文档站，涵盖快速开始、认证、CLI、自托管、工作区、项目、issue、评论、skill、成员权限与集成；
- 英文、简体中文、日文和韩文内容，但并非每个页面在四种语言中都完整对齐。

## 3. Canonical backend 已有能力

### 3.1 默认四模块运行时

状态：**部分实现**。

- 独立 Kratos HTTP/gRPC 进程；
- `/healthz`、`/readyz`；
- Auth、Workspace、Space、System 四模块 Ping；
- 配置校验和优雅停机。

默认组合没有选中各模块的 SQLite 业务服务，不能据此宣称业务 RPC 已上线。

### 3.2 显式 SQLite 领域服务

状态：**部分实现，仅 opt-in 组合**。

- Auth Member：初始化 owner、成员列表、角色修改；
- Workspace Project：CRUD、搜索与删除清理；
- Project 与成员/智能体关系；
- Todo：CRUD、状态、过滤、排序和引用；
- Issue：创建、读取、列表、更新和状态修改，尚无 canonical 删除/搜索；
- Knowledge：创建和读取候选；
- Requirement：保存版本和读取；
- Setting：工作区 JSON 设置与工作区 skill 绑定；
- SQLite 持久化、本地适配器和 gRPC 合同测试。

关键限制：兼容 HTTP、PostgreSQL provider、实时事件、默认运行时选择和整体 cutover 仍是明确延期项。

### 3.3 明确占位的 canonical 能力

状态：**占位**。

- Auth Agent 注册与读取；
- Space Asset 上传、创建版本和读取；
- System Skill 发布/读取版本；
- System Agent Release 发布/升级解析；
- 默认四模块组合中的大部分业务服务。

## 4. 遗留运行时仍提供但未完成迁移的能力

状态：**仅遗留**。以下能力在 README、CLI 文档、根 Makefile 或 `server/**` 中有实现/入口，但不能算作 `backend/**` 已交付：

- 智能体创建、配置、归档、分配和评论触发；
- 本地 daemon 探测并启动 Claude Code、Codex 等 agent CLI；
- 智能体执行队列、消息流、用量、session 恢复和 runtime 心跳；
- 自动化（cron、Webhook、手动触发）；
- 独立 Chat；
- 收件箱与通知中心；
- Runtime 列表、诊断和用量；
- 完整 `multica` CLI 的 workspace、issue、project、agent、skill、runtime、autopilot 等命令；
- PostgreSQL 生产 API、WebSocket 广播和对象存储；
- Docker Compose/Helm 自托管的旧 backend/frontend 组合。

根 `make dev` 当前启动 SQLite 遗留 API，并明确关闭智能体执行和云端功能；根 `make build`、`make test`、`make cli` 也仍进入 `server/**`。因此“根命令可运行”和“canonical backend 已迁移”是两个不同结论。

## 5. 文档声明与当前代码不一致的功能

以下内容应视为文档漂移，而不是当前已确认功能：

| 声明 | 当前证据 |
| --- | --- |
| 当前 Web 有 Agents、Runtimes、Autopilots、Inbox、Chat 页面 | 当前 Web/桌面路由没有这些入口，`packages/core` 也没有相应领域目录。 |
| 五步 onboarding 会创建 runtime 和智能体 | 当前 onboarding 类型只有 `workspace`，只创建/选取工作区。 |
| 当前设置含 repositories、agents、runtimes、autopilots、daemon 等独立标签 | 当前共享设置只有账号、偏好、快捷键、issue、令牌、工作区、成员、角色、标签、自定义属性；桌面额外为更新。仓库/集成能力可能折叠在工作区设置或兼容代码中，但不是独立标签。 |
| 当前仓库有 Mobile app | 根脚本、CI 和文档仍提及 `apps/mobile`，但当前工作树不存在该目录。 |
| 六域基线证明当前 canonical backend | 机器可读六域清单的 backend/protocol/CLI 证据全部指向只读 `server/**`，只能证明遗留基线存在。 |
| 默认开发运行的是新 backend | 根 `make dev` 与 `make start` 实际启动 `server/cmd/sqlite-server`。 |

## 6. 当前最可信的交付判断

- 可作为当前产品演示主线：工作区 → 项目/issue → 需求基线/知识 → Team Control。
- 可作为稳定共享 UI 主线：Web 与桌面共用 core/ui/views，并有大量 Vitest/E2E/桌面测试。
- 可作为 canonical backend 代表性切片：Team Control 控制面。
- 不能宣称已完成：旧 Multica 全功能迁移、默认 backend 业务组合、生产 PostgreSQL cutover、智能体执行链和 Mobile。
