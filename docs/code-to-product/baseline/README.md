本目录记录 `goclaw-team-runtime` 在提交 `3fab1050fb58a7dfea638b6c94f3b2e73745e9b4`（2026-08-12）上的静态功能盘点。

建议按以下顺序阅读：

1. [功能全景](FUNCTION-INVENTORY.md)：从用户视角查看已有功能。
2. [实现状态矩阵](IMPLEMENTATION-STATUS.md)：区分当前产品入口、新后端、遗留运行时和文档声明。
3. [证据与范围](EVIDENCE.md)：查看结论来源、盘点边界和验证限制。

## 一句话结论

当前仓库不是一套已经完成后端切换的单体产品，而是三个并存层次：

- Web、桌面和共享前端已经形成一套围绕工作区、项目、issue、普通任务、知识治理、skill 与 Team Control 的可见产品界面；
- `backend/**` 是唯一可继续开发的后端，其中 Team Control 控制面最完整，其余领域服务多数仍是显式 SQLite 组合能力或占位实现；
- 根目录默认开发、构建和 CLI 命令仍指向只读的 `server/**` 遗留运行时。遗留代码可以解释现有兼容行为，但不能视为已迁移到 canonical backend 的能力。

因此，本基线不使用一个模糊的“完成率”。每项能力按其所在层、入口和验证等级分别标注。

## 状态图例

| 状态 | 含义 |
| --- | --- |
| 已实现 | 当前代码中存在可见入口、调用链和相应测试或契约证据。除非另行注明，不代表本次做过运行验收。 |
| 部分实现 | 主路径存在，但依赖显式组合、缺少关键操作、受功能开关/部署配置限制，或尚未接入默认运行时。 |
| 占位 | 有协议、目录、类型或生成服务，但业务方法明确返回未实现。 |
| 仅遗留 | 只在 `server/**` 或仍指向它的启动链中存在；不属于 `backend/**` 已迁移能力。 |
| 文档漂移 | README、旧产品文档、脚本或保留路径提及该能力，但当前可见入口或 canonical 实现不能支持该声明。 |
| 无法确认 | 静态代码不足以证明真实部署、第三方联通或运行表现。 |

## 维护方式

功能新增、迁移或移除后，应同时更新功能全景、状态矩阵和证据索引。凡是从 `server/**` 迁移到 `backend/**` 的能力，只有在默认运行时选中、兼容边界与确定性验证成立后，才应从“仅遗留/部分实现”提升为 canonical“已实现”。
