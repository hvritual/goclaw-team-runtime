# Native dddgen Scaffold - Execution

## Outcome

Add the native dddgen generation and verification foundation for Workspace,
Auth, Space, and System without changing the current Chi production runtime.

## Included

- Buf module, dependency lock, lint, and generation configuration.
- Native annotations for module and RPC access metadata.
- Primary dddgen modules plus reconciled extension services for every accepted
  Proto service.
- Generated Go, gRPC, Kratos v3 HTTP, OpenAPI, and access-manifest artifacts.
- Module contracts, local/gRPC adapters, `.dddgen` state, contract tests,
  platform extension registry, bootstrap, and architecture import tests.
- Pinned Make targets and CI Proto/contract verification.
- Removal of the repository-local `refactor-goclaw-ddd` skill after its durable
  constraints moved into `CLAUDE.md` and architecture documentation.
- Version-safe staging of externally distributed `dddgen` and
  `protoc-gen-access` from one pinned module version, plus build-metadata
  verification before every generation run.

## Explicitly Deferred

- Registering generated Kratos routes in the existing Chi server.
- Replacing `server/modules/space` or any existing handler with generated module
  application methods.
- Implementing generated persistence seams or creating database migrations.
- Workspace/Auth/System business-use-case migration and SQLite-local cutover.

## Generated Ownership

- Proto source: `server/api`.
- Replaceable output: `server/gen` and files marked generated by dddgen.
- User-owned application method bodies retain the dddgen ownership marker.
- Cross-module imports target only `internal/modules/<provider>/contract`.

## Verification

```sh
make generate
make generated-clean
make verify-ddd-tools
make vet-ddd
make lint-ddd
make test-race-ddd
```

The Kratos HTTP plugin must be v3. The existing v2 binary is incompatible with
the dddgen module templates and is replaced by the pinned bootstrap tool.

The removed `refactor-goclaw-ddd` skill is not restored. Its repository-specific
rules remain in `CLAUDE.md`, while operational generator guidance lives in
`server/docs/architecture/dddgen.md` and the reusable `use-go-ddd-scaffold`
skill.
