## Goal

Complete and make reproducible the clean `rpc/pb` regeneration by normalizing
the pinned dddgen template's fixed `gen/go` imports through a narrow, validated
post-generation command.

## Scope

- Add `backend/cmd/postprocess-dddgen-imports`.
- Replace only the exact import prefix
  `github.com/hvritual/workspace/gen/go` with
  `github.com/hvritual/workspace/rpc/pb`.
- Permit replacements only in:
  - files marked `Code generated by dddgen` below `internal/modules`;
  - the four known unmarked primary module base files and clients/servers;
  - the four dddgen primary Proto files.
- Reject the old prefix in any other file.
- Perform file replacement atomically.
- Rerun batch dddgen, the postprocessor, Buf generation, dependency tidy, and
  all P4 verification gates.

## Non-goals

- No general-purpose text rewriting, pb-tree rewriting, generator fork, business
  implementation, persistence, or runtime cutover.
- No changes outside `backend/`.

## Invariants

- Final generated bindings remain direct Buf output under `rpc/pb` and are not
  postprocessed.
- Proto remains authoritative for pb package identity.
- The postprocessor fails closed for unrecognized old-path occurrences.
- All P4 ownership, isolation, no-HTTP-extension, and no-persistence invariants
  remain in force.

## Dependencies

- P4 clean-generation output and the pinned dddgen/Buf toolchain.
- P4 evidence found exactly 36 stale imports in dddgen-generated extension
  adapter files; `rpc/pb` itself was generated correctly.

## Ordered steps

### P5-S1 — Add narrow postprocessor and finish regeneration

Implement the validated atomic postprocessor, run it over the P4 output, rerun
the complete batch generation pipeline, prove idempotence, and execute all Buf,
Go, architecture, artifact, and repository-scope gates.

## Acceptance criteria

1. No old `gen/go` path remains outside immutable historical plan/journal text.
2. `rpc/pb` contains all generated bindings and `gen/` is absent.
3. The postprocessor has tests for allowed generated files, allowed primary
   files, rejection of unknown files, and idempotence.
4. Fresh dddgen batch output is normalized without manual edits.
5. All P4 acceptance criteria pass.

## Deterministic verification

Run postprocessor unit tests, batch dddgen, the postprocessor, Buf generation,
`gofmt`, `go mod tidy`, Buf format/lint, `go mod verify`, `go test ./...`, and
`go vet ./...`. Compare content checksums across a second generation cycle and
run the P4 path/artifact/scope rejection checks.

## Risks

- An overly broad replacement could hide an unrelated stale import. The
  allowlist and exact prefix make such input fail.
- Non-atomic rewriting could leave partial generated files. Same-directory temp
  files, sync, chmod, close, and rename avoid partial replacement.

## Rollback

Remove the postprocessor and P4 regenerated trees, restore P3 `gen/go` package
options and output, and rerun the P3 pipeline. Do not change `server/`.
